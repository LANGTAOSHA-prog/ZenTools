# 数据驱动架构

## 核心思想

ZenTools 的所有页面内容均由 `data/tools-data.json` 驱动，而非手动编写 HTML。一个 JSON 文件定义了 279 个工具的完整元数据，三个不同场景的渲染引擎读取同一份数据。

## 数据流

```
                    tools-data.json (654KB, 12619行)
                    ├── 13 个 categories
                    └── 279 个 tools
                           │
          ┌────────────────┼────────────────┐
          │                │                │
          ▼                ▼                ▼
    首页渲染            全局搜索          互补推荐
    (main.js)          (tool-ui.js)      (tool-ui.js)
          │                │                │
          ▼                ▼                ▼
    分类卡片            搜索下拉          推荐卡片网格
    工具网格            (多语言匹配)       (relatedMap)
    AI工具专区
```

## 首页渲染

`main.js` → `init()` → `fetch('/data/tools-data.json')`:

1. 读取 `data.categories` → 渲染分类卡片到 `#categoryPreview`
2. 读取 `data.tools` → 渲染工具卡片到 `#toolsGrid`
3. AI 工具 (category === "AI工具") → 渲染到 `#aiGrid`
4. 搜索过滤: 用户输入 → 在 tools 数组的 `name` / `description` 中匹配

## 全局搜索

`tool-ui.js` → 导航栏搜索框:

1. `loadTools(cb)` 懒加载 toolsData (fetch 或直接读取 `window.toolsData`)
2. 用户输入 → 匹配所有工具的 `name` / `name__en` / `name__ja` / `name__vi` / `description` / `category`
3. 渲染为下拉建议列表: `renderDropdown(query)`

## 互补工具推荐

`tool-ui.js` → 内部 `relatedMap` + toolsData:

1. 预定义 30+ 对互补关系: `{ "pdf-merge": ["pdf-split", "pdf-compress"], ... }`
2. 当前工具 slug → 查找 `relatedMap` → 获取推荐 slug 列表
3. 在 toolsData 中匹配推荐 slug → 渲染为卡片网格

## 分类导航

`loader.js` → `renderCategories()`:

1. `CATEGORY_ICONS` 对象定义 12 个分类的 emoji 图标映射
2. 硬编码分类到目录的路径映射 (如 "AI工具" → "/ai/index.html")
3. 渲染到 `#categoryRibbon` 导航条

## 数据驱动的优势

- **一致性**: 一个 JSON 修改，全站同步更新 (名称、描述、URL)
- **可搜索**: 所有工具名称和描述集中在 JSON 中，搜索索引构建简单
- **可脚本化**: Python 脚本可批量处理 JSON (校验、统计、批量添加)
- **可缓存**: Service Worker 可单独缓存 tools-data.json，离线仍可搜索

## 数据驱动架构的限制

- **无动态路由**: 每个工具需独立 HTML 文件 (279 个页面)，因为 GitHub Pages 不支持 SPA 路由
- **首次加载大**: tools-data.json 654KB，首次加载较慢 (但 SW 缓存后极快)
- **无法部分更新**: 修改一个工具需要重新传输整个 JSON
